Nexora — AI Video Generation Pipeline

AI Engineering Project · Solo Build

A FastAPI backend that turns a topic and a target duration into a fully narrated MP4 through one HTTP call — orchestrating an LLM script writer, a TTS narrator, word-level audio alignment, and a video generation model into a finished, subtitled video on GPU cloud infrastructure.

Python FastAPI PyTorch / Transformers Qwen LLM Chatterbox TTS (ONNX Runtime GPU) WhisperX FFmpeg Docker RunPod GPU Cloud GitHub Actions CI

This is a private, production codebase — not publicly linkable. Everything below is drawn directly from the project's own docs and git history (91 of 92 commits authored solo).

The problem

Producing a narrated short-form video today means chaining together separate tools by hand: write a script, record or synthesize narration, cut clips to match the audio, source or generate visuals, and burn in subtitles — each step manual, and easy to get out of sync with the others. Nexora collapses that entire workflow into a single API call: give it a topic and a target duration, and it returns a finished MP4 with narration, matching visuals, and burned-in subtitles, with audio and video timing guaranteed to match automatically.

How a video flows through the pipeline

Seven stages run for every job, each persisting its output to disk so the pipeline is resumable and any stage range can be re-tested in isolation.

  1. ScriptA Qwen LLM writes a narration script sized to the requested topic and target duration.
  2. NarrationChatterbox TTS (ONNX Runtime, GPU) synthesizes the full script into one continuous narration WAV — no sentence-by-sentence stitching.
  3. AlignmentWhisperX re-transcribes the narration to produce word-level timestamps — the single timing authority for every downstream stage.
  4. ChunkingThe narration is split into 3–6 second semantic chunks along word boundaries — one chunk becomes one video clip.
  5. PromptsQwen generates a cinematic visual prompt per chunk, describing the shot the video model should generate.
  6. VideoA distilled video generation model renders one clip per chunk, generated to match that chunk's exact duration.
  7. RenderFFmpeg trims, concatenates, and muxes the clips with the narration and burned-in subtitles into the final MP4, duration-matched to within 1%.

What I built

Sole engineer on the project — 91 of its 92 commits are mine, from initial architecture through GPU deployment.

Pipeline architecture
Orchestration
Architected the resumable stage-pipeline orchestrator (script → narration → alignment → chunking → prompts → video → render), where every stage persists its output to disk so any stage range can be re-run in isolation without redoing earlier work — the same code path powers both the full production endpoint and a stage-by-stage testing API. Built the GPU residency manager that dynamically loads and offloads the LLM and TTS models around each stage so the video model always gets full VRAM headroom on a single GPU pod.
Reliability engineering
Narration integrity
Built an automated narration-integrity gate that re-transcribes generated audio and checks word-error-rate, coverage, and repeat-ratio before accepting a take, with temperature/seed retries and a one-shot script-shortening fallback for persistent failures. For the chunked-TTS path, added independent per-chunk verification — boundary-word matching, hallucinated-word detection, duration plausibility, and onset-energy checks — so one bad TTS chunk regenerates on its own instead of failing the whole job.
Deployment & CI
Infrastructure
Containerized the service for GPU cloud pods (RunPod) with a fast git-pull dev loop for iterating on a live pod, and set up a CPU-only GitHub Actions CI that exercises the entire API route surface in a mock mode (no GPU required) on every push — the Docker image itself only rebuilds when dependencies actually change, keeping the code → test → deploy loop fast.
Quality gates
Automated testing
Built a "golden reference" test harness with 10 automated gates checking artifact presence, narration integrity, resolution, and audio/video duration alignment on real GPU hardware — the release gate every change has to pass end-to-end before it ships.
